# Model 18 — AI Quant Trading Terminal (BTCUSD)

> **Status:** Research/prototype software. The live executor can submit real orders to MetaTrader 5. Test in a demo account first. This project is not financial advice and does not guarantee profits.

## 1. Overview

Model 18 is a Python-based BTCUSD automated-trading prototype connected to MetaTrader 5 (MT5). The intended operator workflow is simple: start the terminal with `launch_terminal.bat`, monitor the Streamlit dashboard, and independently verify actual order activity in MT5. When the setup is correct and the configured model/strategy conditions are met, the executor can submit an entry and apply the configured stop-loss/take-profit logic. No trade is guaranteed to occur; the market conditions, MT5 connection, broker permissions, model files, and execution checks must all be valid.

The project has four main parts:

1. **Live market data feeder** — reads BTCUSD ticks from MetaTrader 5 and appends them to a CSV file for data collection.
2. **Data processor** — converts raw tick data into features for model training.
3. **PyTorch classifier** — learns to classify examples as `HOLD`, `BUY`, or `SELL`.
4. **Live executor + Streamlit dashboard** — loads a trained model, evaluates live ticks, may submit orders, and publishes status for the dashboard.

The main live entry point is `launch_terminal.bat`. See [`WORKING.md`](WORKING.md) for the operator guide with embedded screenshots.

## 3. How the files connect

### A. Collect live ticks (optional data-collection pipeline)

```text
MetaTrader 5 terminal / broker
        │
        ▼
live_dom_feeder.py
        │ appends every 100 ticks
        ▼
hft_crypto_dataset.csv
```

- `live_dom_feeder.py` connects through the MetaTrader5 Python package.
- It selects the symbol `BTCUSD` and records `Time`, `Bid`, `Ask`, `Spread`, and `Velocity_ms`.
- It writes batches of 100 rows to `hft_crypto_dataset.csv`.
- This collector is **not launched by `launch_terminal.bat`**; start it separately when you want to collect data.

### B. Prepare the training data

```text
hft_crypto_dataset.csv
        │
        ▼
Abondend_Model_18/hft_data_processor.py
        │ calculates Mid_Price, Price_Change,
        │ Tick_Imbalance, Velocity_Z, Spread_Z
        ▼
training_dataset.csv
```

The processor derives:
- `Mid_Price`: average of Bid and Ask.
- `Price_Change`: change in mid-price from the previous row.
- `Tick_Imbalance`: rolling sum of up/down/unchanged tick direction over 50 rows.
- `Velocity_Z`: velocity relative to its rolling 50-row mean and standard deviation.
- `Spread_Z`: spread relative to its rolling 50-row mean and standard deviation.

The first rolling-window rows are removed because their rolling statistics are incomplete.

### C. Train the neural network

```text
training_dataset.csv
        │
        ▼
Abondend_Model_18/train_hft_ai.py
        │ creates labels from price 200 rows ahead
        │ trains a 5-input / 3-output PyTorch network
        ▼
train.pth
```

The model input features are:
`Price_Change`, `Velocity_Z`, `Spread_Z`, `Spread`, `Tick_Imbalance`.

Labels are generated using the mid-price 200 rows ahead:
- `BUY` when the future price is at least $5 higher.
- `SELL` when the future price is at least $5 lower.
- `HOLD` otherwise.

The network has 5 input features, hidden layers of 64 and 32 units, and 3 output classes. The training script runs for 100 epochs and saves a PyTorch `state_dict`.

**Important path detail:** The training scripts use relative filenames. Run them from the directory containing the relevant CSV files, or update the paths. As currently written, `train_hft_ai.py` saves `train.pth` inside `Abondend_Model_18/`, while `auto_executor.py` expects `Model_18/train.pth`. Copy the trained weights to the expected location or change `MODEL_PATH` so both scripts point to the same file.

### D. Run live execution

```text
MetaTrader 5 terminal / broker
        │
        ▼
auto_executor.py ───── loads ─────► train.pth
        │
        ├── reads BTCUSD ticks
        ├── computes live features
        ├── gets model probabilities
        ├── may submit BUY/SELL orders to MT5
        └── writes latest status
                    │
                    ▼
              live_status.csv
                    │
                    ▼
             hft_dashboard.py
                    │
                    └── Emergency Kill button creates kill_switch.txt
                                      │
                                      ▼
                                auto_executor.py stops
```

`auto_executor.py`:
- connects to MT5 and selects `BTCUSD`;
- loads `train.pth`;
- calculates live tick features after collecting 50 observations;
- checks the model's BUY/SELL confidence against an 85% threshold;
- if the conditions pass and there is no active position for its magic number, sends a market order;
- uses a configured lot size of `0.01`, a nominal $150 stop distance, and a nominal $300 target distance;
- writes price, spread, confidence, active trade, and PnL to `live_status.csv`.

These values are hard-coded in `auto_executor.py`. Confirm that they fit your broker's symbol specification, contract size, tick size, account currency, and risk limits before any live use.

## 4. What happens when `launch_terminal.bat` is clicked?

1. It attempts to terminate prior command windows with the configured window titles.
2. It deletes `bot_running.lock`, `kill_switch.txt`, and `live_status.csv` if present.
3. It starts `auto_executor.py` in a separate command window.
4. It waits three seconds.
5. It starts the Streamlit dashboard in another command window.

The batch file does **not** start `live_dom_feeder.py`, the data processor, or the training script. Those are separate data-collection/training steps.

## 5. Setup

### Requirements

- Windows
- Python 3.10/3.11 recommended (use a version supported by your installed PyTorch and MetaTrader5 packages)
- MetaTrader 5 desktop terminal installed, logged in, and connected to a broker/demo account
- A broker account that exposes the symbol under the exact name `BTCUSD` (some brokers use a suffix or different symbol)
- Python packages:
  - `MetaTrader5`
  - `torch`
  - `numpy`
  - `pandas`
  - `streamlit`

Install packages in a virtual environment from the project directory:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install MetaTrader5 torch numpy pandas streamlit
```

If PowerShell blocks activation, use the Windows Command Prompt activation command instead:
`.\.venv\Scripts\activate.bat`

### Start the terminal

1. Open MetaTrader 5 and log in to a **demo account**.
2. Check that `BTCUSD` is visible in Market Watch.
3. Make sure the trained weights exist at `Model_18\train.pth`.
4. Open a terminal in the `Model_18` directory and run:

```powershell
.\launch_terminal.bat
```

Or double-click `launch_terminal.bat`.

The batch file uses `python` and assumes Python and the required packages are available on PATH/in the active environment. If the dashboard does not start, run `python -m streamlit run hft_dashboard.py` manually to inspect the error.

### Collect training data separately

With MT5 connected and `BTCUSD` available, run from the project root:

```powershell
python live_dom_feeder.py
```

Stop with `Ctrl+C`. The collector appends batches to `hft_crypto_dataset.csv`. Back up important data before replacing or deleting it.

### Process and train

The scripts in `Abondend_Model_18` currently use paths relative to their own working directory. From PowerShell:

```powershell
cd .\Abondend_Model_18
python hft_data_processor.py
python train_hft_ai.py
```

Ensure the expected raw input file is present in that folder and the processor's output is in the same folder. Then place the resulting `train.pth` at the location expected by `auto_executor.py`, or update `MODEL_PATH`. Review the path and feature consistency warnings below before relying on the model.

## 6. Safety and known issues to fix before live trading

This README describes what the supplied code currently does; it does **not** certify that the strategy is safe or profitable.

1. **Feature normalization mismatch:** Training standardizes each feature using the training dataset's mean and standard deviation, but does not save those statistics. The live executor sends raw features to the model. Training and inference inputs therefore do not match. Save the training means/stds and apply exactly the same transformation live.
2. **Feature calculation mismatch:** Training computes rolling `Velocity_Z` and `Spread_Z` from the dataset. The live executor estimates them from rolling buffers differently; verify the exact definitions, units, warm-up, and standard-deviation convention match.
3. **Model file path mismatch:** The training script saves `train.pth` relative to its current working directory; the executor loads `train.pth` from the project root. Align these paths.
4. **Collector/processor paths:** The collector writes its CSV in the current working directory. The processor reads `hft_crypto_dataset.csv` from its current working directory. Run them in the intended folder or use explicit paths.
5. **Kill switch reset:** `launch_terminal.bat` deletes `kill_switch.txt` at startup. The dashboard creates it when the kill button is pressed. This is a simple file-based stop signal, not a broker-side emergency close; it does not automatically close open positions.
6. **Order handling:** Check `tick` and `symbol_info` for `None`, validate SL/TP against broker stop-level rules, inspect order retcodes/errors, and handle unsupported filling modes. The current code uses `ORDER_FILLING_IOC` directly.
7. **Risk sizing:** A fixed lot size and price-distance SL do not guarantee a fixed monetary loss. Calculate risk using broker contract specifications, account currency, tick value/size, commission, and slippage. Add maximum daily loss, maximum position count, and a manual confirmation/demo-only mode.
8. **Labeling and validation:** The training labels use future prices, which is appropriate for constructing targets, but evaluation must be chronological and leakage-free. The current training script reports training accuracy only; it does not provide a held-out test set, walk-forward validation, fees, spread/slippage simulation, or proof of profitability.
9. **Feature/target alignment:** Ensure the processor output and training script use the same schema and that each feature is available at the actual decision time.
10. **Lock-file behavior:** `auto_executor.py` removes an existing lock file on startup, so the lock does not reliably prevent multiple instances. Use a robust single-instance mechanism if needed.
11. **Dashboard control:** The dashboard reads a CSV updated by another process and can briefly encounter a partial write. Atomic file replacement or a local API/socket would be more robust.

**Do not run this on a live account until these issues have been reviewed and tested.** Start with offline tests, then MT5 Strategy Tester/demo testing, and only consider live use after independent validation.

## 7. GitHub and confidential files

A `.gitignore` only prevents matching, untracked files from being added by Git; it does not hide files from anyone who can access the repository, and it does not remove files already committed.

Before publishing the repository, review whether you want to share:
- `hft_crypto_dataset.csv` and `training_dataset.csv` (raw/processed market data, potentially large);
- `train.pth` (trained model weights);
- logs/status files such as `live_status.csv` and `bot_running.lock`;
- any broker credentials, account IDs, terminal paths, tokens, or private configuration that might be added later.

Never commit passwords, API keys, broker credentials, or private account details. Keep the repository private while reviewing it if you are unsure. If a secret was committed, remove it from the repository history and rotate/revoke it; deleting it in a later commit is not enough.

## 8. Troubleshooting

- **`MT5 Initialization Failed`:** Open MT5, log in, confirm the terminal is connected, and verify the Python package can access that terminal.
- **Symbol not found / no ticks:** Check the broker's exact BTC symbol name and enable it in Market Watch.
- **`train.pth` not found:** Align the training output path with `MODEL_PATH` in `auto_executor.py`.
- **Dashboard says it is waiting for backend:** Check the backend command window for errors and confirm `live_status.csv` is being written.
- **No trades:** The 50-tick warm-up, confidence threshold, position checks, market hours/liquidity, and broker rejections can all affect execution. Do not lower the threshold without backtesting.
- **Dashboard kill button clicked:** It creates `kill_switch.txt`; verify the backend stops. Manage any open position separately in MT5 because the script does not close it automatically.
